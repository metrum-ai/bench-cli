# Platforms

Metrum AI Bench CLI is a **client**. It runs on your measurement host and talks to
whatever OpenAI-compatible endpoint you point it at. Server hardware support is
therefore “whatever your serving stack exposes,” not a Bench-managed
accelerator matrix.

---

## Client install targets

| Path | Platforms |
| --- | --- |
| GitHub Release binaries | Linux `x86_64` / `aarch64` `*-unknown-linux-gnu` (glibc **2.17** floor); macOS Darwin `x86_64` / `aarch64` |
| From source | Rust **1.85+** on a host that can build the crate |
| Homebrew | Formula generated for tap publish when `HOMEBREW_TAP_REPOSITORY` is configured; not a standalone GitHub Release install path |

Not shipped as release targets:

- musl / Alpine-style static Linux archives
- OpenSSL-linked builds (TLS is rustls)
- **Windows** - no release archives. Building from source on Windows may work
  for development but is not a supported or smoke-tested install path for 1.0.

Verify release archives with the published `.sha256` and optional Sigstore
bundle before unpacking.

### Optional Cargo features

| Feature | In GitHub Release binaries? | Purpose |
| --- | --- | --- |
| `otlp` | Yes (`--features otlp`) | Strategic OpenTelemetry export (`--otlp-endpoint`) |
| `tokenizer` | No | Local `--tokenizer` counts; build from source with `--features tokenizer` |

## Serving stacks (Docker first)

Bench measures an OpenAI-compatible HTTP endpoint. **Bring up vLLM or SGLang
with the vendor container images.** Installing server wheels with `pip` on a
stock cloud GPU image commonly fails on JIT kernel compilation (missing `g++`,
mismatched CUDA headers, missing prebuilt kernels for new SM versions). That
path burned hours in field trials and can make a working GPU look broken.

### Preferred: vendor images

```bash
# vLLM (example). Map host 8000 → container 8000; adjust model and GPUs.
docker run --gpus all --shm-size=32g -p 8000:8000 \
  vllm/vllm-openai:latest \
  --model Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0 --port 8000

# SGLang (example).
docker run --gpus all --shm-size=32g -p 8000:8000 \
  lmsysorg/sglang \
  python3 -m sglang.launch_server \
  --model-path Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0 --port 8000
```

Run **Metrum AI Bench CLI on the same host** (loopback URL). Driving a public
cloud IP from a laptop puts WAN RTT into TTFT and can invert close comparisons.

Before a long GPU run, probe the OpenAI-compatible endpoint from the client:

```bash
metrum-ai-bench-cli preflight \
  --url http://127.0.0.1:8000/v1/chat/completions \
  --api-key dummy --model YOUR_MODEL
```

Preflight checks reachability, a unary chat probe, streaming first-token smoke,
and a short latency sample. It cannot see CUDA toolchains or GPU inventory on a
remote host; when the serve path is wrong, prefer the vendor containers above.

Shadeform / cloud helpers in this repository already launch these images via
`scripts/live/shadeform.sh` (`vllm/vllm-openai:latest`, `lmsysorg/sglang`).

### Advanced: pip on bare metal

Only when you control the CUDA toolkit, compiler, and wheel/SM matrix. Expect
to install a matching CUDA toolkit, `g++`, and often still hit FlashInfer /
DeepGEMM JIT failures on newer architectures. Prefer Docker when comparing
hardware.

### Hardware / server caveats

| Area | Status | Notes |
| --- | --- | --- |
| NVIDIA datacenter (Hopper H100 and similar) with vendor Docker | Validated in live smoke paths | Use official vLLM / SGLang images |
| NVIDIA RTX PRO 6000 Blackwell (`sm_120`) with vendor Docker | Works with caveats | Quantized / FP4 paths need images that ship prebuilt kernels; bare-metal pip + JIT is known-blocked for many users |
| Bare-metal pip + CUDA 12.8 / 13 + FlashInfer on Blackwell | Known-blocked / fragile | Header and SM detection issues; do not treat as a Bench defect |
| AMD Instinct | In progress | Smoke matrix in-repo is NVIDIA-first today |

### SGLang and sliding-window models

SGLang pre-allocates a sliding-window attention (SWA) pool sized by
`--max-running-requests`. On some sliding-window models, high values refuse to
start or collapse usable KV capacity. In field trials, concurrency **128** was
a practical ceiling where **256/512** failed on H100 for a SWA model, while
vLLM admitted higher concurrency on the same card. When comparing vLLM vs
SGLang, record `--max-running-requests` (and any SWA-related flags) in the SUT
`runtime.config` field so the matrix is not silently mis-specified.

## Smoke and publication matrix

Smoke results in the repository
([`docs/SMOKE_RESULTS.md`](https://github.com/metrum-ai/bench-cli/blob/main/docs/SMOKE_RESULTS.md),
package `1.0.0-rc.1`) are **NVIDIA-only**. AMD Instinct coverage is in
progress.

Fleet-wide comparison, history, and attestation are Platform concerns, not this
OSS client. One Bench process drives one endpoint or one configured pool.

## Security notes for shared hosts

- Do not put credentials in endpoint files committed to source control.
- Run summaries may record client `environment.hostname`. Use
  `--redact-hostname` (or `--require-sut`, which implies redaction) when
  publishing or sharing logs.
