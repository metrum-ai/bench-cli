# Metrum AI Bench CLI v1.8.0 release notes

## Breaking metric and outcome changes

Headline streaming `ttft_s` now measures the first actual reasoning or visible
output delta. In v1.7.2 it measured the first visible answer. Use the separately
reported visible-answer TTFT to preserve answer-latency comparisons. The
reachable 0.1.82 source also used visible TTFT: do not assume the new headline
restores its definition. Confirm any wrapper's exact version and cohort before
comparing with its historical numbers.

Completed reasoning-only length streams are recorded as
`reasoning_truncated` without failing by default. They do not contain an
answer. Enable strict reasoning truncation, or `--ci-safety`, for
answer-required checks. Answer goodput excludes unanswered requests.

Output token throughput includes reported reasoning tokens and uses a
first-measured-send to last-terminal-completion window. If usage is incomplete,
full token throughput is unavailable rather than silently understated.
Non-reasoning completion throughput requires a server-reported reasoning split
and is not necessarily an exact answer-token count. Cohorts, fields, schemas
and the TTFT SLO meaning have changed; version-aware readers must migrate
before comparing old and new results. See [METRICS.md](../METRICS.md),
[OUTPUT_SCHEMA.md](../OUTPUT_SCHEMA.md), and
[REASONING_MODELS.md](../REASONING_MODELS.md).
